V3 차세대 SaaS 연동을 위한 JSON 정책 체계 전환, 크로스플랫폼 정책 통합, 자동화 파이프라인 구축

사내 SaaS 관리 솔루션(Onemanagement) 연동을 위한 XML→JSON 정책 포맷 전환 및 단일 원천(JSON Schema) 기반 CI/CD 자동화, x-mapping 무코드 설정 매핑, AI 기반 1,300개 정책 전수 검증 및 Windows/Linux 정책 체계 일원화

(~600개 → 약 500개 슬림화)

(스키마 수정만으로 대폭 단축)
1,300개 검증 수동 불가 규모의 전수 테스트
야간 배치 자동화로 완수

공통 JSON 체계로 일원화
📌 추진 배경: 사내 SaaS 환경을 겨냥한 차세대 관리 제품(Onemanagement) 출범에 따라, V3가 기존 레거시 XML 대신 표준 JSON 정책을 수용해야 하는 요구사항이 발생했습니다. 이에 단순 1:1 포맷 포팅에 머무르지 않고, 수년간 누적된 XML 정책의 레거시 부채를 과감히 정리하고, 개발자 경험(DX)과 정책 배포 생산성을 극대화하기 위해 스키마 기반 자동화 및 무코드 설정 매핑 아키텍처로 전면 재설계를 주도했습니다.

⚠️ 도입 전 (Before) — 기존 XML 정책 체계의 한계

파편화된 다단계 수정 프로세스

정책 수정/추가 시 관리제품팀 저장소(Bitbucket Repo)의 다수 XML 파일(요소·속성 기입)과 XML 스키마 문서를 각각 수동 수정하고 PR을 생성해야 하는 번거로운 수작업 발생

C++ 파싱 코드 수작업 & 동기화 부담

정책이 추가될 때마다 V3 소스코드에 C++ 파싱 로직을 직접 추가해야 했으며, 관리제품 레포의 XML 정책과 V3 내부 파싱 코드 간 지속적인 스펙 동기화 관리 부담 존재

레거시 정책 누적 및 분류 모호성

약 600여 개의 방대한 정책 중 미사용 레거시 정책들이 방치되어 불필요한 용량 차지, 정책 증가에 따라 카테고리 구분이 명확하지 않아 정책 성질 파악 곤란

플랫폼별 정책 체계 파편화

Windows V3와 Linux V3가 각각 분리된 정책 체계를 운영하여 플랫폼 간 중복 개발 리소스가 투입되고 팀 간 소통 비용이 과다하게 발생

✅ 도입 후 (After) — 개선 성과 및 아키텍처 혁신

Single Source of Truth & CI/CD 자동화

JSON Schema 파일 하나만 수정하면 Bamboo CI/CD 파이프라인을 통해 JSON 정책 파일이 자동 생성되고, 관리제품팀 Bitbucket Repo에 자동 Commit/Push 및 PR까지 생성 (관리제품 레포 수동 작업 100% 제거)

x-mapping 무코드(No-Code) 설정 자동 매핑

JSON Schema 내 비정규 속성(x-mapping)을 도입하여, 별도 C++ 파싱 코드 작성 없이 JSON 정책 데이터를 V3 엔진 내부 설정으로 곧바로 1:1 자동 매핑함으로써 개발 공수 획기적 단축

레거시 100여 개 정리 & 다각적 카테고리화

미사용 레거시 정책 약 100개를 발굴·제거하여 슬림화하고, 정책의 성질과 보안 도메인에 맞춘 다각적 카테고리 분류 체계를 도입하여 정책 명확성 및 관리 편의성 극대화

Windows & Linux 크로스플랫폼 통합

Windows V3와 Linux V3가 공통 JSON 정책 체계를 공유하도록 일원화하여, 플랫폼 간 정책 파편화를 해소하고 개발 리소스 절감 및 제품 간 소통 활성화

🤖 AI(Copilot, Claude Code) 활용 및 철저한 품질 검증 체계

새로운 JSON 정책 적용 시 기존 XML 정책과 동일하게 V3 엔진에 100% 무결점으로 반영되어야 하므로, AI 코딩 도구를 적극 활용하여 검증 도구군과 파이프라인을 자체 구축했습니다.

🔄 1. XML ↔ JSON 1:1 정책 변환 툴 개발 (Python)

기존 XML 정책과 신규 JSON 정책 간 스키마 구조를 1:1로 정확하게 상호 변환하고 매핑 관계를 검증하는 변환 엔진 개발

📸 2. C++ 정책 스냅샷 & 정밀 Diff 비교 도구 개발 (C++)

정책 적용 후 V3 내부 설정 상태를 완벽 캡처하는 스냅샷 도구 및 두 스냅샷 간 설정을 필드 단위로 정밀 비교하는 고성능 Diff 도구 자체 개발

🌐 3. 실운영 XML 정책 수집 크롤러 개발 (Selenium)

테스트 신뢰성을 높이기 위해 실제 운영 환경에서 실사용 중인 다양한 XML 정책들을 관리 콘솔에서 자동으로 일괄 다운로드하는 웹 크롤러 구축

⚡ 4. PowerShell 기반 E2E 테스트 자동화 파이프라인

V3 초기화 → XML 적용 → 스냅샷 캡처 → V3 재초기화 → JSON 적용 → 스냅샷 캡처 → Diff 비교 전 과정을 일괄 수행하는 스크립트 구축. 수작업이 불가능한 대규모 테스트를 야간 배치로 무인 자동화

🛡️ 5. 구조화된 Allowance(허용 목록) 차이 분석 및 무결성 확보

서로 다른 약 1,300개 정책을 실행·비교하는 과정에서 발생한 수많은 Diff를 심층 분석하여 분류: 1) JSON 정책 결함, 2) 기존 레거시 XML 파서의 버그, 3) 미사용 정책으로 인한 무해한 차이점. 이 중 무시 가능한 항목을 구조화된 Allowance 규칙으로 체계적 분리·관리하여 실제 결함에 집중함으로써 완벽한 설정 무결성 입증

⚠️ 도입 전 (Before) — 문제 상황

업무 부하

일 평균 10건 이상 이슈 생성, 제작 시간 최소 30분 ~ 최대 1시간 이상 소요. 5년 이상 단순 툴 개선 수준에 그침.

인력 의존성

6개월 단위로 채용되는 학생 인턴이 담당하여 인력 변동에 따른 업무 연속성이 결여됨. 교육·멘토링·업무 인수인계에 개발자 역량 투입 발생.

일관성 부재

기술지원 담당자마다 일관되지 않은 요청 양식으로 요청 내용을 이해하고 해석하는 데 어려움이 따름.

수동 테스트

V3를 직접 설치하고 수동 테스트하는 과정에서 최소 10분 ~ 최대 30분 이상 소요. 기능 추가/버그 수정 시 1시간 이상 개발 및 테스트 시간 필요.

✅ 도입 후 (After) — 성과

Full 자동화

요청 내용 해석 → 제작 → 배포까지 Full 자동화. 이슈 생성과 동시에 자동 제작 시작, 커스텀 마스터가 제작되기까지 약 5분 소요.

자동화 테스트

가상화 환경에서 Robot Framework를 이용한 테스트 자동화. 빠른 제작 및 긴급 요청에 원활히 대응. 테스트 소요 시간 5~10분.

요청 양식 표준화

Rule 기반의 정형화된 템플릿을 통해 요청 양식이 일관화됨. 오류 시 어느 부분이 잘못되었는지 파싱 결과로 전달 (컴파일 오류 출력 방식과 유사).

유지보수성

V3 설정에 대한 메타데이터를 구조화된 JSON으로 구현. 짧은 시간 안에 새로운 설정 추가 가능 (기능 추가 시 작업 시간 몇 분 이내).
